# STORY.md — Visualization Project Description · Pizza Snack Play

## ① Intent alignment

**Audience and occasion.** A project-review / showcase submission. The reader is an evaluator who
has not seen the application and will spend a few minutes on the deck. They are technically
literate but not a specialist in this stack. The occasion is *assessment*, not internal training —
so the deck must read as evidence, not as instruction.

**Core goal.** After the last page the evaluator should believe three things and be able to repeat
them:

1. This is a **real system in production** for a real school, not a demo — the numbers are measured
   from a repository, not estimated.
2. The design makes specific failures **impossible** (half-published classes, double-claimed duty
   dates, cross-class edits) rather than merely unlikely.
3. The project was **generated by prompt under a verifiable loop** — intent, constraint, evidence,
   acceptance, artefacts — and that loop is documented well enough to be inspected.

**Length.** 16 pages. Hero quota for 16 pages: 4 heroes (25%).

**Visual tone.** Analytical · evidence-led · restrained · warm-neutral · no hype.

**Content boundaries.**
- *Must cover:* the source artefact and the pain it caused; the three roles and the boundary
  between them; the `draft → locked → published` machine; the technical layer stack; how prompts
  drive generation; measured metrics; honest limits.
- *Will not cover:* feature-by-feature walkthroughs, screenshots of every page, the school's
  personal data, or any number that cannot be traced to a file in the repository.
- *Never touch:* invented metrics, "revolutionary/industry-leading" language, emoji, or a claim
  about impact that has no verifier behind it.
